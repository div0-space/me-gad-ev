The workshop: built with VC

How Maciej and the agents build The Journal: editing, a static publisher, two language editions and a separate member archive.

Start with the reading experience

The Journal is a publication, not a conversation export. Working with agents, I choose threads, organise the chronology and edit the writing. me·gad·ev remains the project’s personal wordmark; The Journal is the journal’s name.

Stable addresses, stable order.
Every article has its own address. A later correction does not move it to the top of the archive: order describes publication, not the last file save.
Two languages, one publication.
The English edition uses the main addresses; Polish uses the /pl/ prefix. The language switch leads to the equivalent page. Headings use Monaspace Xenon and reading text uses Monaspace Neon; the fonts are local.
Finished artwork.
Original Art API illustrations are retained as ready-to-serve assets, including SVG artwork and the PNG share image. Reading does not require a connection to the image-generation service. Course materials are not used as prompts for public artwork.

How we divide the work

Vibecrafted, or VC, helps us organise agent work. Maciej sets the direction, provides necessary access and decides what to publish. Agents read sources, prepare changes and identify what they actually checked.

The journal’s historical implementation used four external workers and one integrator. The cuts covered publishing, artwork, the shared reading shell and the process account. The integrator assembled specific changes into one publication. The current typography, writing and language correction takes place in the main checkout; it is not another run of that earlier comparison.

One publisher, separate roots

The offline Python publisher reads our writing and generates HTML, RSS feeds and agent indexes. Public sources and output are separate from private ones. English member records remain under /members/journal/; Polish records use /members/pl/journal/, within the same access boundary.

The gate uses one-use browser-bound OAuth state with PKCE. The guarded handler serves files with private, no-store. Public RSS, share metadata and llms.txt contain no member narrative.

The dispatch formation

The number of plans can change; nine configurations remain the common comparison axis. A fair comparison of results requires the same plan, code baseline and acceptance conditions.

What we publish

The open articles tell the story of our collaboration and the website. Course details, our task chronology and the chart derived from task data stay in the member archive. Raw sessions, OAuth material, receipts and answer texts do not enter public sources.
